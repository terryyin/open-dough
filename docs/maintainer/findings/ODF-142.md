## ODF-142 — Abbreviated delivery SHAs produce misleading refusals

An abbreviated published-base SHA is accepted as an argument but compared without normalization, causing misleading delivery refusal and fallback publication without observation.

- **Source:** [pygardon / DD-220](https://github.com/terryyin/pygardon/blob/9751952fe19dc48ead34987157c9909e9ff9a10c/DearDough.md#odf-142--managed-delivery-refused-a-fast-forward-candidate-with-rebase-left-the-pre-rebase-sha-as-the-candidate).
- **Follow-up:** [Normalize commit identities before delivery comparisons](https://github.com/terryyin/open-dough/blob/c3c453854fe95a53342026225f3c7b38a209c23f/.planning/seeds/SEED-008-worktree-branch-trunk-sync.md#normalize-delivery-commit-identities) (`SEED-008#normalize-delivery-commit-identities`, plan `c3c45385:.planning/slice-plans/342-normalize-delivery-commit-identities/PLAN.md`), delivered 2026-10-22; not resolved. Response revisions: `1443f1f2` resolves a hexadecimal base to its full commit ID after the fetch in `publishExecutionIncrement`, so a unique abbreviation gives the full ID's decision, receipt, `suffixBase`, `beforePush` comparison and fresh recovery facts; `bbce29a4` stops a base that is not a hex object ID (including `HEAD` or a branch), unknown, ambiguous or not a commit as `unresolvable-base`, naming the input, its `problem` and the rerun with the full ID from the receipt, and names the argument form in the `deliver` usage and `trunk-publication.md`. Proof: `execution-increment-publication-base-identity.test.mjs` (full versus ten-character base on identical fixtures for an unchanged, advanced, new and already-published target), `execution-increment-publication-unresolvable-base.test.mjs`, and the fresh-candidate recovery case; full `npm test` passed. Release: unreleased after `0.3.68`. Remaining limits: a delivery that throws before its fetch settles keeps the supplied base in fresh recovery; managed delivery still establishes the coordinator's observer before the refusal, registering no revision; resume's `--suffix-base` and `--validated-candidate` still require full IDs. Field effectiveness is unmeasured: the next ordinary eligible use should record input form, decision, failed calls, recovery effort and any false refusal.
