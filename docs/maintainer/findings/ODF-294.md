## ODF-294 — An observability slice's proof never crossed the delivery path its purpose named

**Meaning:** An observability slice proves an upstream logger in a test harness but never exercises the downstream production log path named by the outcome.

- **Follow-up:** Open, unqueued.
- **References / identity:** Pygardon / DD-268 → ODF-294. One 0.3.63 execution. The production default warning level suppressed INFO messages; caplog green proof could not establish owner-visible phase attribution. The owner accepted the incomplete attribution, so no correction is falsely recorded. Related outside-in proof issues do not establish the same cause. A slice added INFO log lines "so the production run in slice 10 is
attributable", and its proof observed them only through pytest `caplog`.
Production runs at the default `warning` level, so no line reached the
container log during the owner-run measurement. Outside-in proof stopped at
the logger, not at the log the consumer reads.
