## ODF-413 — An observation is recorded before its output is read

**Meaning:** During slice acceptance a coordinator records a source-review commitment as observed, pointing at output that does not exist yet or was never read, so the defect that observation should have caught is published.

**Follow-up:** Open, unqueued; not resolved.

**Identity / assessment (2026-11-03):** Shared recording facet of Doughnut DD-334; the Springdoc schema-name collision is Doughnut's local DD-335. Related to ODF-232 (acceptance publishes an explicitly unobserved fact) and ODF-357, distinct: an `observed` record written before reading. One execution on 0.3.82. Maintained guidance assessed at `325f9de8a1f635a44b0071cf0660a2593a21f6b9`.

### Retained source evidence — doughnut / DD-334

**Source:** [doughnut / DearDough.md](https://github.com/nerds-odd-e/doughnut/blob/0373e4129d8dbc29189e08bdcb0075969eee0f2c/DearDough.md).

**Source mapping:** doughnut / DD-334 → ODF-413.

During slice 1 acceptance, the coordinator recorded the source-review commitment "The `GET` is described in OpenAPI" as observed, pointing at generated output that did not exist yet. The API client was regenerated afterwards, during delivery, and nobody read the generated schemas. The generated spec reused the existing entity `Answer` schema for the nested export record, without three of its fields. The slice 2 implementer noticed a possible name clash for its own new record; the coordinator then inspected the spec, found the slice 1 defect, and opened obligation G1 to return it to slice 2. The shared problem is recording the observation before reading its output; the Springdoc schema-name collision that produced the wrong contract is Donut's and is recorded as DD-335 in [Donut Retrospective Findings](DonutRetrospectiveFindings.md#dd-335).
