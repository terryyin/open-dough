# Compare story proof through merge resolutions

I used the [original story][story], the [plan’s outside-in proof][plan], and one detached, shallow checkpoint at `d03cf60f11e9f9599ae99db17932a029e854ecf8`. The checkout had one reachable commit, no refs or remotes, and no planning or docs directories in the working tree. Original hosted CI outcomes are **unknown**. The results below are fresh runs of the historical code and tests.

## Findings

- The homepage tests distinguish A, B and C by revision, run link and wall time. The proof table also distinguishes B and C execution times. Matching Review boundary tests still refuse both kinds of unsafe attribution while Intent exposes CI proof.
- The precise Summary tests passed after a deliberate substitution of Branch proof for Landed proof. They check distinct identities and exact output, but the fixture assigns identical measured results to B and C. The browser reached the substituted branch for the selected entry, folders and compact file.
- Three plan examples have narrower fixture evidence than their names imply. The E7 later fast-forward leaves the earlier landing on the new first-parent line. The A-retained gap journey supplies known B/C revisions with no builds. The owning-resolution fixture edits a branch merge before the actual trunk landing. None of these fixture limitations makes the related baseline tests fail.
