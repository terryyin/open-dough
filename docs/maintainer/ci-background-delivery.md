# Background CI delivery

The installed execution skill supports an explicit ten-minute background CI
handoff for a directly invoked, still-running interactive Claude Code
coordinator in Story Branch Mode. The original session, checkout, child identity
and existing repair authority remain bound to one detached mailbox observer.
The handoff validates the exact latest accepted and registered publication.
[Runtime instructions](../../src/skills/dough-execute-plan/references/ci-background-handoff.md)
define the commands and receipts.

The native asyncRewake Stop hook waits on local mailbox changes. Pending and
success generate no model feedback. An actionable registered failure makes one
exclusive durable attempt before native exit2 feedback. Native feedback has no
acknowledgment, so local status retains delivery uncertainty even after output;
manual recovery inspects the original session and attempted event before any
retry. Cancellation, expiry, a closed session and lost observation remain
visible limitations. Handoff preserves resources and grants no retirement.

Codex, Cursor, print/exited Claude sessions, automated dashboard runners,
Trunk Mode and ordinary wrap-up closure retain the existing bounded completion
operation. Cold resume, automatic rearming, broader runtime transfer/reboot/
mixed-version cutover, dashboard lifecycle integration and automatic retirement
have no new background-delivery implementation. Native continuation evidence
alone does not establish installed support for those forms.

## Native acceptance

Claude Code2.1.296 / Haiku5.5 with manual one-time approval has accepted installed
same-session delivery: managed local bare-remote publication and registration,
explicit pending receipt, coding-turn end, later actual custom-provider failure,
then one original-session wake with retained context and repair instructions.
The model, permission policy, workspace and original session stayed bound.
The actual provider pipeline supplied discover/diagnose evidence rather than
injecting an event or native input. Owned native, observer and waiter processes
ended cleanly. Existing native asyncRewake feasibility also covers busy,
permission, structured question, draft preservation and parent/child isolation.
[ADR0005](../adrs/0005-cross-tool-validation-accepted.md) still governs acceptance
for an affected new route or ordinary release.

Runtime process tests separately cover pending/success silence, exact owner/SHA,
concurrent hooks, cancellation, expiry, original-session departure and uncertain
broken feedback. Installer tests preserve the old synchronous handler, add the
new async wrapper once, keep local policy/unrelated handlers and refuse edits.

## GitHub request ownership

The existing shared request owner remains the acquisition path for GitHub
providers. Startup requires an authenticated greeting; a connectable owner that
no longer answers can be replaced through the existing fenced generation and
shared allowance. A responsive incompatible owner still refuses. Native custom-
provider acceptance does not prove request-owner access on restricted hosts.
