## Goal and scope

A maintainer gets a measured recommendation for one Codex boundary policy.
Test a fresh coordinator after an accepted slice and fresh workers starting
from slice briefs. Keep the delivered behavior, decisive proof, independent
review and human decision rights in both runs. Measure each role's peak and
all agent effort through acceptance. One matched pair tests the policy as a
whole. Other hosts, a released default, a configurable cap and changes to
story sizing are outside this trial.

Use slices 1–3 of the [original own-branch session review plan](https://github.com/terryyin/open-dough/blob/2280ba9293c87033f094e6eb53358264d13de75b/.planning/slice-plans/705-keep-own-branch-session-results-for-review/PLAN.md)
at `2280ba9293c87033f094e6eb53358264d13de75b` on two isolated fixture
remotes. They exercise committed capture after retirement, retained
uncommitted changes at Done, and an explicit branch/worktree handoff. Judge the
captured endpoint, changed paths and contents, and which launch owns them.
Use the original plan and pre-change fixture and withhold the solved patches
and later execution transcript from both arms. Pin the same Open Dough
payload in both arms separately from the product revision. Compare the
current policy on this bounded case with the candidate. The historical run
informs case selection and supplies no control result for the new pair.

No local product suite is a gate for the planning-record change. In each
experimental arm, use the checkout's focused commands at the actual writer
and read boundary, with the source plan's consumer proof. Use
`caffeinate -s -i` on AC power for long local runs. On battery, defer an
unattended run, or use `caffeinate -i` for an attended run and check the sleep
log afterward. Follow the [maintained macOS sleep guard and power condition](../../../Distribution/tests/local-test-resources.md#machine-sleep-on-macos)
and the shared [failure policy](../../../Distribution/src/skills/dough-execute-plan/references/failure-policy.md)
in every arm, delegation brief and repair handoff.

## Current decisions

- Try the existing smaller-story rule in both arms. Shorter worker briefs
  alone leave the coordinator's growth untouched. Host compaction has a
  different quality and measurement boundary. A deliberate restart tests
  whether Git and the existing plan can carry the judgment the next slice
  needs, together with a worker brief that can recover original sources.
- Reuse the plan, Git, native rollouts, CI receipts and current effort reader.
  The native guidance comparison harness has reusable isolation and assessment
  practices but its shipped cases drive a single coordinator thread per arm.
  Use the isolated replay, with no new runner, checkpoint store, launch option
  or telemetry contract. The test checkout and its fixture remotes own all
  experimental writes. Use separate stopped sessions rather than overlapping
  writers at handoff.
- [ADR 0005, Native validation and A/B testing](../../../docs/adrs/0005-cross-tool-validation-accepted.md)
