## ODF-264 — Broad startup reads lose required context to truncation

**Meaning:** An agent batches whole workflow references or unbounded metadata beyond the response budget, loses requested passages to truncation and repeats retrieval before delegation.

- **Follow-up:** Response implemented on 2026-10-22, not yet released (after 0.3.68; record the containing release when it ships) — SEED-010#bound-startup-guidance-retrieval, story-branch commits `fc62c171` and `144b436f`.
  - **Response:** `dough-execute-plan/SKILL.md` now has a "Read guidance at each boundary" table. Each row is one tool result, read when its boundary is reached and never combined with another row; on Codex the skill body is its own read. `read-budget-guidance.test.mjs` fails any row over 30,000 bytes and names the row and the overflow. That is Claude Code's 30,000-character Bash limit, which is below Codex's `TruncationPolicy::Tokens(10_000)` at 3.5 bytes per token.
  - **Before:** the former startup paragraph named about 33,700 bytes (~8,400 tokens at bytes ÷ 4) before the first delegation, and 107,400 bytes (~26,800 tokens) across its adjacent boundaries; 125,100 bytes (~31,300 tokens) with the skill body on Codex.
  - **After, per row (bytes):**
    - skill body 19,090
    - established start 2,922
    - execution workspace 18,790
    - Codex arming 21,071
    - first delegation 20,711
    - return acceptance 8,543
    - delivery 24,517
    - arming on other hosts 27,463
    - CI notification 26,892
    - finish 16,141

    The largest is about 6,900 tokens.
  - **Known gap:** the correction SEED-010#name-required-passages-in-boundary-rows (queued first) adds passages that three rows' own passages require, such as `fresh-increment.md` at delivery. Per-host savings remain for Story 13's post-release Evaluation.
- **References / identity:** Distinct from ODF-158: the source identifies an execution deviation under already-applicable targeted-retrieval guidance, whereas ODF-158 concerns the cost of required broad reads. Distinct supplied executions are retained below; repeated tool calls within an execution do not increase recurrence. Some execution releases and all unrecorded event times remain unknown; no general saving is measured.
