## ODF-482 — A pre-Take merge base causes a false source-freshness hold

**Meaning:** Several best merge bases can coexist after history-preserving sibling imports. Choosing the pre-Take base can misidentify the comparison for a valid Take.

**Follow-up:** [Keep source-freshness checks usable after a contributor merge](../../../.planning/seeds/SEED-400-source-freshness-with-a-valid-take.md#keep-freshness-with-a-valid-take) — SEED-400#keep-freshness-with-a-valid-take. Response implemented by `03b29b34e` (Take resolution in its own module), `444c34536` (the comparison starts from the best common base that holds the Take) and the following commit on the same story (several Taken bases serve as one while every compared record reads the same at each; a record that differs between them is refused `ambiguous-base`, naming the bases and the record). Replayed with the changed script, both retained graphs report `unchanged`: Open Dough SEED-285#trace-landed-proof-timing, branch `50f4f4f1e` against trunk `1c784a6d6` from base `8554eb19e`; Lizard SEED-058#process-pr-569, branch `03695185` against trunk `60b2fb59` from base `e12c55f8`. On such a graph a trunk story amendment is `amended` and absorbed, and a graph whose best bases all lack the Take is refused `not-taken-at-base`, naming each base. **First containing release:** none yet (unreleased; findings maintenance adds it). Not resolved from delivery alone.

**References and limits:** A distinct graph-selection issue from [ODF-403](ODF-403.md). Source coverage and later integration remain evidenced in the original execution.
