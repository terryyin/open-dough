## Replacement premises that remain open

- Qualification has real-Git coverage for range/path/policy interpretation, but not watcher state choosing the baseline, no install/restart, retries or restore. Existing qualification cases alone cannot discharge rows17–24. Any smaller stateful proof must drive the existing owner.
- `settled-attempt-reconciliation.spec.ts` covers settlement and persisted reconciliation refusal/acceptance. It does not drive stale/unrelated publication comparisons or a partially accepted snapshot, so it does not currently replace row34.
- `cursor-runner-last-held.spec.ts` observes actual keep/hangup/kill key persistence. It does not prove automatic revival, scope or UI. It cannot by presence alone replace row40. SEED-287’s accepted branch lifetime precondition can reduce incidental initial UI without removing those observations.
- Repeat admission siblings exercise old-receipt,104s, Taken and unsupported-provider rules, with their own repeated collection cost. Raw-verdict siblings exercise missing/unknown provider conclusions, not the six row27–32 outcomes. They are candidates for shared canonical evidence and must be timed if credited, not free substitute proof.
- Phone and tablet context journeys differ: phone covers a covering panel; tablet exercises Maximize/Restore. Native touch must still demonstrate independent pane scrolling and real overflowing text; layout assertions or scroll assignment cannot replace that.

## Count and experiment implications

The working target remains30 from45 (one-third fewer). Only one currently inspected removal has supported same-fault evidence elsewhere: SEED-287’s standalone post-HUP C restart is covered by its existing restart journey, at the cost of including that retained proof. That is not yet a reduction for this checkout, nor proof that30 is feasible. The existing `production-watcher.spec.ts` restart consumes runner/client/next/development state from its earlier serial cases; its current usable proof requires that full7-case family. Counting it in the replacement selection can therefore add more checks than the one removed until a smaller genuine lifecycle is established. No free net1 reduction is credited. Many serial watcher cases describe successive phases of one lifecycle and can possibly be regrouped, but regrouping alone neither removes paid staging nor makes the loop fit default case time. Do not claim all25 watcher checks duplicate qualification.

Proposed order remains real deployment/source preparation (slice2) → minimum real watcher lifecycle/stateful qualification (slice3) → actual request-owner controlled deadline (slice4), followed by minimum UI/session/repeat evidence. The combined baseline quantifies cost; no untried saving is accepted here. The material count target is a hypothesis until each replacement’s assertions and fault observations are accepted.
