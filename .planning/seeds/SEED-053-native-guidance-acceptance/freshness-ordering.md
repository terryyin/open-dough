# Freshness ordering native acceptance

Extension of [Accept guarded local preparation, commit and publication on each host](../SEED-053-native-guidance-acceptance.md#guarded-local-delivery-prerequisites).

**Freshness ordering extension:** For planned Story Branch implementation
returns, observe source and named-sibling checks before refactoring and expensive
boundary/whole-suite proof. The coordinator must receive and inspect terminal
results before dependent operations; sequential awaited calls in one uninspected
orchestration, or checks launched alongside delivery, fail this requirement.
Include these representative cases:

- An already-landed named sibling affects behavior relied on by the slice:
  attribute and reconcile it first; refactor/proof then cover the reconciled tree.
- `amended` holds dependent work through absorption, source review and an
  `unchanged` recheck; conflict/refusal retain the stop. An unchanged source plus
  affected sibling still holds the candidate, done mark, commit and publication.
- Unchanged source with no affected named landing (including accounted-for and
  unrelated controls) proceeds with existing sufficient proof, no extra full run
  or unrelated-work hold. A later amendment/landing reaches a fresh delivery
  check and renews only affected proof.

**Ordering evidence:** Pending separately for Codex, Cursor and Claude Code.
The credential-free amended replay stops before staging and does not observe
implementation-return/refactor ordering. Historical guidance walks and static
navigation checks do not discharge these requirements. Reuse unaffected
installation/transport evidence only on a matching guidance, mechanism,
environment and observed boundary; select later native sessions by unresolved
risk under ADR 0005. No paid run is authorized by recording this extension.
