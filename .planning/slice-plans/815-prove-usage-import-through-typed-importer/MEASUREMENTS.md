# Usage history backend measurements

The original baseline was the published claim at
`04b96eb9d673e08e36ef33ad2cc08e13c42ed729`. The candidate was
`52ad3cb656562a57324ad8d129db596712903b04` with the Slice 7 harness
and E2E setup edits. Both timed runs passed the same 54 selected file paths
through the maintained backend runner on Node 24.21.0 with two workers, the
16-core Mac on AC power and `caffeinate -s -i`. The family used Playwright
before and Node Vitest after. Natural one-minute load ranged from 7.60 to
15.61 before and 6.85 to 10.19 after. This is a before/after sample, with
lower load during the candidate run.

Elapsed time dropped 59.0% and summed case time
dropped 66.6%. The separate CLI-start runs passed
the same test selections as their timed counterparts. A Node preload logged
only the operation when the entry point was
`dashboard/server/importUsageHistory.ts`. The original count ran in an
isolated detached checkout of the claim with a locked npm install. The
candidate count covered import/read defaults and output, two injected
failures and two cross-process lock writers. The separate Agent Effort CLI
and other process boundaries are outside the usage import tally.

replacement-failure case pairs its earlier title about keeping the previous
history readable with its current title naming the injected command error.

slower cases the column identifies the retained work visible in the test
source. Individual operation costs were not timed.
