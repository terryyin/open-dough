## ODF-396 — Source-derived consumer terms flood module-move listings

**Meaning:** Automatically derived generic import/path/symbol terms in an ordinary module move produce roughly a hundred noisy consumer matches and repeated dispositions.

**Follow-up:** Open, unqueued; not resolved.

**Identity / assessment (2026-11-01):** Uncertain relationship retained separately from ODF-350 broad supplied terms and ODF-352 changed data keys. The derivation source differs; no shared cause or missed consumer is established. It is an independent cost of current tracing, not a reason to remove indirect proof. When a structure slice moved symbols between modules, the consumer trace added
terms derived automatically from changed paths, import paths and declared
names (`ci_session`, `holders`, `shas`, `job_cpuset`, `__init__.py`). Its
listing then ran to roughly a hundred files, mostly matched only by those
generic terms, and each one needed a disposition. Possibly the same problem as
ODF-350 (broad supplied terms) or ODF-352 (terms derived from a data file), but
the terms here came from ordinary source paths, so the match is uncertain.
