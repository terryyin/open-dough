## ODF-516 — Planning omits size decisions for files a slice will edit

**Meaning.** Plans size primary implementation files while overlooking a document or record that a slice also edits. A delivery-time size check then requires a seam decision or restructuring after implementation.

**Follow-up.** Open and unqueued.

### Lizard / DD-490

[Source at the reviewed revision](https://github.com/terryyin/lizard/blob/8cfd437f990d49019b7465266288b6c0156ce3b7/DearDough.md#L118).

The proof file was already oversized, and planning omitted the reorganization
decision. This is the same planning gap seen in the other ODF-516 accounts.
The refactor stop led to a successful extract in the source execution. The
shared finding remains open.

When slice planning names an already-oversized suite as the only proof home and supplies no extract seam or size exception, post-change refactor correctly stops on the file-size gate and delivery waits on a human reorganization choice. Prefer naming the cohesive extract (or an authorized exception) in the plan before execution when the suite is known to exceed 250 lines.
