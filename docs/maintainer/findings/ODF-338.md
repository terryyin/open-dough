## ODF-338 — Concurrent slices invalidate proof in one checkout

**Meaning:** Parallel slices share a checkout whose uncommitted inputs, moving HEAD, file swaps and formatter activity invalidate each other's proof.

**Follow-up:** Open, unqueued; not resolved.

**Identity and limits:** New concrete issue at the supplied execution provenance. Related to ODF-225 (stashing invalidates a running reader) and ODF-331 (in-place baseline swaps), but this execution demonstrates simultaneous slice and commit-state interference; keep the broader coordination failure separate. No repair, general effect or current recurrence is inferred from an unknown execution release. Current maintained guidance assessed: `f274a3d0c729504bf8ce00614bf3cd236b7e088b` (source through 0.3.71); this is not substituted execution provenance.
