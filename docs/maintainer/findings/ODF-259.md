### Retained evidence — Pygardon / DD-501 (2026-11-13)

**Source mapping:** [Pygardon / DD-501](https://github.com/terryyin/pygardon/blob/7cd45787a9d4485c52ea1853e4aa86883fd9ad19/DearDough.md#L838). The same eight-hour execution budget expired on the custom adapter. The excluded merge added an observed completion consequence.

Severity: severe (owner, 2026-11-13). Shared Open Dough process; the owner asks the Open Dough project to take it up as soon as possible.

The CI observer ends with `CI_MONITOR_UNAVAILABLE` ("Execution observation budget expired after 28800000 ms") while a story is still executing. Nothing then tells the coordinator how to obtain the completion receipt that wrap-up's retirement gate requires ("a `success` completion receipt for the final accepted SHA whose shutdown is confirmed"), so it falls back to hand-written polling. Hand polling by exact SHA cannot apply the existing `not_required` rule: a revision whose own changes are all CI-ignored never gets an attempt, and its verdict is its applicable basis ancestor's. The poll waits forever, or until a timeout, for a run that will never start.

### Recommended fix

1. Make completion observation recoverable after expiry: on `CI_MONITOR_UNAVAILABLE` (budget expired) the execution and wrap-up instructions name one managed command that re-establishes observation of the authorized target, or performs the completion wait directly, and produces the same completion receipt the retirement gate checks. Never leave the coordinator to poll by hand.
2. Expose the effective verdict as one read-only command usable by wrap-up, landing and release: given a SHA, it returns the revision's own attempt, or for an ignored-only (`not_required` / `path_excluded`) revision its basis — the nearest attempted ancestor whose difference is ignored-only — with that basis's state and SHA.
3. State the basis rule for merge landings explicitly: the nearest attempted ancestor reachable through either parent whose difference to the landing is ignored-only, never the first parent or the newest trunk attempt by default.
4. Size the observation budget to the story, or renew it at each slice publication, so a story that spans days does not lose observation before wrap-up.
