## Context (unnumbered)

- Reason (Goal): a developer reviewing Codex or Claude Code usage should still see a finished task when a new model appears, get an estimate, and learn which model needs a rate-card update.
- Settled baseline (Goal; Key examples): when GPT-6.2 appeared, the Codex rate card left 19 recent finished tasks unpriced. The November 15 Codex card gives no point for GPT-6.2 Astra.
- Scope limit: the estimate supplies only a missing model rate. An estimated rate and missing usage describe different facts.
- Architecture: the server derives the actual-model/substitute pair with the point, so chart, task detail and warning describe the same calculation; the updated card retires the estimate without rewriting usage history (ADR 0002, ADR 0008).
- Token Index reference units come from the tool's reference model; for Codex the denominator is GPT-6.1 Sol's input rate.
