## ODF-336 — A territory publisher identity mistakes another session for its owner

**Meaning:** A stable territory-wide publisher ID identifies two live coordinator sessions as the same owner, so an existing claim is misleadingly returned as this session's.

### Retained source evidence — Pygardon (2026-10-25)

**Source:** [Pygardon / DD-335](https://github.com/terryyin/pygardon/blob/d52a15b73182864bde8daba5498936c170d05380/docs/process-findings/publication-and-workspaces.md).

**Source mapping:** pygardon / DD-335 → ODF-336.

The coordinator ran `execution-start.mjs start` for a queued story with the stable publisher ID it already held from an earlier launch. Another agent session had already taken the story under that same publisher ID and was editing in its own worktree. The start returned `existing` ("work already Taken under your claim"), with that session's claim SHA, so the identity check could not tell the two sessions apart.

- Execution: SEED-120#story-release-docker-proof-repair (plan 394), during its pause for the supplier story SEED-120#story-release-recover-restarting-candidate
  - Provenance: Timestamp: 2026-10-23T10:41:54+09:00; Tool: Claude Code; Model: claude-opus-5-5; Open Dough release: 0.3.69
  - Evidence: start with `--publisher-id dashboard-territory.local-pygardon --identity SEED-120#story-release-recover-restarting-candidate` returned `{"status":"existing","publishedSha":"a90838b9b…","created":false}`. `a90838b9b` is Yumi-chan's Take at 10:12, and its worktree `.worktrees/recover-a-crash-looping-candidate-caught-between` held uncommitted `deployment/failed_candidate_recovery.py` and test edits from 10:17–10:20.
  - Observed effect: Nothing was written. The coordinator found the other session only by inspecting `git worktree list`, then stopped instead of executing a second time. The other session finished the story at `c746f6ead`. Inference: A publisher ID shared by every launch from the dashboard territory identifies the territory, not one coordinator. An `existing` result therefore does not prove the claim belongs to this session; following it would have duplicated execution against live edits.
