but nineteen reported durations exceed one second (max 1,501 ms); 21 observed

ten cases fell 11,093→8,687 ms and five File Proof cases 4,897→3,528 ms.
The relative and wording families remain expensive. These sums are neither
wall nor CPU time, and cloud/lifecycle differences limit causal attribution.

The worst keyboard Show % case has 459 ms Navigate, about 144 ms ordinary
Before Hooks, 170 ms After Hooks, 196 ms actual actions, 30 ms mount evaluation,
and about 508 ms reads/assertions. Shared beforeAll is excluded. The first
three alone leave only 227 ms before the strict target, almost consumed by
the real actions. Read reduction alone cannot promise the missing 550–600 ms.
The selected different strategy must reduce incidental loading and complete
observation/lifecycle cost together, with measured margin before extension.
