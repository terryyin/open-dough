## ODF-323 — A caller-written plan-status mutation survives a later delivery refusal and is not safe to retry

**Meaning:** Guarded fresh delivery applies the coordinator's own plan/status update before its later preparation checks. When a later check refuses, the update stays applied, and retrying with the same unbounded or non-idempotent update refuses again or advances the wrong slice.

- **Response:** **released in v0.3.69; not resolved** — `SEED-010#retry-selected-slice-status` (Terry selected it first on 2026-10-22; story and plan recoverable at `ea162a1d60ae86a9cb6c55886eeca02a4ab63a8b:.planning/seeds/SEED-010-learn-from-execution-retrospectives.md#retry-selected-slice-status` and `ea162a1d60ae86a9cb6c55886eeca02a4ab63a8b:.planning/slice-plans/348-retry-selected-slice-status/PLAN.md`). Guarded fresh delivery of planned work now marks the selected slice `done` itself (`src/skills/dough-execute-plan/scripts/selected-slice-status.mjs`), changing only that slice's real `Status:` line as the shared plan reader bounds it and leaving an already-done slice unchanged, so the same request repeats after a preparation refusal. It refuses before staging a missing, duplicated or unreadable slice, or another slice newly `done` against the committed plan; the caller-written `plan.update` is removed and refused as `context`. Proof: `execution-increment-fresh-slice-status.test.mjs` (retry after `staged whitespace` commits only the selected status plus the coordinator's own plan edit; fenced `Status:` untouched; refusals) and `execution-increment-fresh.test.mjs` (obligations before and after, also when already done), with both discrimination checks failing as expected when the idempotence or other-slice guard was disabled. Implementation `2541671c`. First containing release: `v0.3.69`, verified below. Added preparation burden: none; the coordinator writes one fewer operation. Next eligible-use observation: the first ordinary planned fresh delivery retried after a preparation refusal under a release that contains this response, in any client; compare its final plan with the retained examples above.
- **References / identity:** Open Dough / DD-328 and Doughnut / DD-320 → ODF-323: two distinct executions (Codex, release unknown; Claude Code, 0.3.67). The concrete issue is the ordering of the caller-supplied mutation before later checks plus caller-authored retry safety. Open Dough's plan 330 published one premature slice status; Doughnut's retry was made idempotent before it ran. Open Dough / DD-326 (below) is related counterevidence, not an occurrence: the updater itself failed and the fail-closed gate published nothing. Current guidance assessed: Open Dough `e2e7bfcd` (installed 0.3.68); this is the review revision, not substituted execution provenance.
