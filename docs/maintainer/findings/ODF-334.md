## ODF-334 — Exact-SHA polling bypasses the completion operation

**Meaning:** A coordinator polls for an exact-SHA attempt instead of using the bounded applicability-aware completion operation, so excluded commits never satisfy the loop.

**Follow-up:** Open, unqueued; not resolved.

**Identity and limits:** New concrete issue at the supplied execution provenance. Related symptoms elsewhere do not establish a common cause. The bounded completion operation already exists. The observation is noncompliance and a distinct release-verdict need, not a missing shared implementation. Current maintained guidance assessed: `f274a3d0c729504bf8ce00614bf3cd236b7e088b` (source through 0.3.71); this is not substituted execution provenance.


### Retained source evidence — Pygardon (2026-10-25)

**Source:** [Pygardon / DD-327](https://github.com/terryyin/pygardon/blob/d52a15b73182864bde8daba5498936c170d05380/docs/process-findings/ci-observation.md).

**Source mapping:** pygardon / DD-327 → ODF-334.

To decide release readiness the coordinator wrote ad-hoc shell loops waiting for a terminal attempt of an exact SHA. For a commit changing only CI-ignored paths no attempt is ever created, so the loop could never finish; the owner noticed and asked for analysis. Open Dough's bounded completion operation would have classified it `not_required` on its passing parent.
