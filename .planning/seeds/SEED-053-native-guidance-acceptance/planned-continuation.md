# Planned continuation acceptance cases

These cases extend the canonical
[SEED-053#quiet-dashboard-completion](../SEED-053-native-guidance-acceptance.md#quiet-dashboard-completion)
acceptance home; they create no separate identity or queue assignment.

**Covered work:**
[SEED-145#continue-execution-into-wrap-up](../SEED-145-no-news-is-good-news.md#continue-execution-into-wrap-up)
and [plan 333](../../slice-plans/333-continue-execution-into-wrap-up/PLAN.md).
Observe installed planned execution invoking Story Wrap Up in the same session
without a separate instruction when no human choice remains, and preserving
genuine stops. This extension grants no native-run, release or rollout authority.
No native continuation case has been run or accepted on Codex, Cursor or Claude Code.

Select representative fresh sessions by unresolved risk, preserving the existing
explicit-no-wrap-up `execution-review` cases as stop controls. Required cases:

- Successful planned execution with review, and with an explicit automatic-review
  skip: actual review/skip and records-only publication precede the applicable
  completion receipt, then same-context wrap-up begins without an intermediate
  recap or confirmation. Include a quick attempt that continued into a plan
  representatively; wholly planless completion retains its separate journey.
- A valid correction, recorded process finding and explicitly authorized product
  reorder: wrap-up queues one canonical correction first, preserves active
  follow-up records and finding evidence, applies only the authorized compatible
  change, and closes only the predecessor without executing the correction.
- A missing correction field, unapproved product recommendation or human-owned
  constraint: marked attention names the actual decision/action and consequence;
  required active records, workspace and terminal/session remain usable. Include
  an explicit review/retain stop and pending explicit background CI as controls.
- Execution succeeds but required closure publication, CI/shutdown or retirement
  fails or is held: no successful closure claim or premature resource removal;
  recovery resumes the first unfinished operation without repeating accepted
  publication, completed review or the canonical correction's queue entry.
- Direct use makes no dashboard contact. With supplied launch context, a quiet
  execution boundary submits nothing; actual closure, applicable integration CI
  and shutdown and safe retirement precede the final quiet reporting operation
  and matching receipt. A genuine stop retains exact-message attention reporting
  and resumability; an execution success report alone never marks session Done.

Cover Story Branch integration and Trunk Mode closure risks, local-only/no-push
authority, and direct versus dashboard invocation across the representative
selection. For every affected requirement on each host, retain fresh evidence or
justified reuse with the matching guidance, setup and observed boundary. Prior
callback feasibility and runtime closure proofs can support unchanged mechanisms;
they do not prove the agent's new continuation choice. Do not rewrite earlier
observations or call instruction assertions native behavior. Functional
implementation may close while this acceptance remains pending; affected release
waits for acceptance or an explicit human-owned
[ADR 0005](../../../docs/adrs/0005-cross-tool-validation-accepted.md) exception.
